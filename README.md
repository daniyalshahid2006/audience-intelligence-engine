# Audience and Campaign Intelligence Engine

A small web application for a Pakistani women's lawn-suit brand. It analyses social media posts and comments
(Instagram, TikTok and Facebook) and answers five marketing questions using clustering, anomaly detection and
evidence-based recommendations.

> **Important:** all data in this project is **simulated**. It demonstrates the method and is not real customer data.
> Every row carries a `data_source = simulated` label so simulated and real records can never be mixed by accident.

## The five questions

1. **Which content attracts attention?** (reels, product photos, influencer posts, styling videos, sale and Eid content)
2. **What does the audience want?** Comments in English, Roman Urdu and Urdu are grouped by need.
3. **Which patterns are unusual?** Posts that behave very differently from similar posts.
4. **Which audience needs should the brand address?** Price, delivery, availability, sizing, fabric and more.
5. **What should marketing do next?** Actions backed by numbers.

## How to run (Windows PowerShell)

    python -m venv venv
    .\venv\Scripts\Activate.ps1
    pip install -r requirements.txt
    python src\run_pipeline.py      # rebuilds every result in outputs\
    streamlit run app.py            # opens the web app at http://localhost:8501

The simulated data (`data/raw/posts.csv`, `data/raw/comments.csv`) and all results (`outputs/`) are already in the
repository, so `streamlit run app.py` works immediately. To regenerate the data from scratch:

    python src\generate_posts.py
    python src\generate_comments.py
    python src\check_data.py        # 8 integrity checks

No Java or Spark is needed.

## Data

* **Posts (Table A):** `post_id, brand, platform, campaign, content_type, product_category, likes, comments_count,
  shares, views, days_since_post, data_source, collection_date, sim_anomaly`. Brands are fictional (Brand A to E).
  `views` and `shares` are missing for some posts, as they often are on real platforms.
* **Comments (Table B):** `comment_id, post_id, comment_text, language_type, topic, sentiment, purchase_intent,
  data_source`. Table B is a sample of up to 15 comments per post; `comments_count` in Table A is the true total.
* The data is generated with a fixed random seed (42), so it is reproducible. Patterns are built in on purpose
  (for example, sale announcements attract price questions) so the analysis has something real to find.
* **Hidden labels:** `topic` (comments) and `sim_anomaly` (posts) record what the simulation planted. The models
  never see them; they are used only at the end to check how well the methods worked.
* No platform was scraped and no real user data was collected.

## Methods

1. **Text cleaning:** lower-casing, removing emoji and punctuation, collapsing repeated letters ("pleaseee"),
   merging Roman Urdu spelling variants (kitne / kitnay, bohat / bht), unifying look-alike Urdu letters and
   keeping Urdu script. Distinct Roman Urdu texts fall from 3,593 to 186.
2. **Content analysis (Q1):** an *attention index* compares each post with the typical post on the same platform
   (1.00 = typical). It needs no view count, so it is fair to posts that hide views. Posts under 7 days old are
   excluded because they are still gaining likes.
3. **Comment clustering (Q2, Q4):** TF-IDF features and K-Means. A small bilingual word list links the same need
   across English, Roman Urdu and Urdu. The number of clusters (10) is chosen automatically by silhouette score.
   Clusters are named by their dominant wording.
4. **Anomaly detection (Q3):** each post is compared with its *expected* engagement given platform, content type,
   brand and age, then an Isolation Forest flags the 3% most unusual posts.
5. **Recommendations (Q5):** rules driven by the results above, each shown with its evidence.

## Results (simulated data)

| Question | Finding |
|---|---|
| Q1 | Reels (about 1.46x a typical post) and influencer posts (about 1.35x) attract the most attention; product photos the least (about 0.60x). Sale announcements start the most conversation. |
| Q2, Q4 | 10 audience groups. Praise is about 22% of comments, then price questions (about 13%), discount questions (about 12%) and availability (about 10%). |
| Q3 | 90 posts flagged, including giveaway-style comment spikes, outperformers and underperformers. |
| Q5 | 12 recommendations, for example putting prices inside sale announcements, because they draw the most price and discount questions. |

**Validation against the hidden labels:** the comment clusters match the planted topics 98.5% of the time
(adjusted Rand index 0.981). The anomaly detector finds about 69% of the planted anomalies, and giveaway-style
comment spikes are found completely.

## Limitations

* The data is simulated and template-based, so results are cleaner than real social media comments would be.
* A small hand-made English / Roman Urdu / Urdu word list links the three languages; it was designed for this
  simulated vocabulary and would need extending for real comments.
* The comment samples (up to 15 per post) understate how much a busy post is discussed.
* Real data would need permitted access (official platform tools or exports) and should be stored with its own
  `data_source` label.
